# hyprland-dms-config

My [Hyprland](https://hypr.land) + DMS (DankMaterialShell) config on Nobara (Fedora 44),
to be adapted for left-handed use like my niri setup
([niri-dms-config](https://github.com/mirko-geno/niri-dms-config)).

## Contents

```
backup.sh           # saves the current system config into this folder
restore.sh          # installs what is missing (Hyprland, DMS, ...) and puts the config back
hyprexpo.sh         # builds the hyprexpo overview plugin (run by restore.sh, and after Hyprland updates)
hypr/
├── hyprland.lua    # main Hyprland config (Lua, Hyprland 0.57+)
├── stack.lua       # custom "stack" layout + its binds (Super+Alt+T / Super+Alt+Space)
├── workspaces.lua  # workspaces 1-4 on the landscape monitor, 5-8 on the portrait one
├── floating.lua    # Super+V: floating windows get a fixed size and are centered
├── hyprexpo.lua    # Super+Tab: workspace overview (hyprexpo plugin, built by hand)
├── xdph.conf       # screen-sharing portal: cursor visible, no repeated picker
└── dms/            # Hyprland files generated by DMS, loaded with require() at the end of hyprland.lua
dms/
├── config/         # ~/.config/dms: settings.json, monitors.json, themes, Firefox/Zen css
└── state/          # ~/.local/state/dms/session.json: current wallpaper, monitor profile
alacritty/
├── alacritty.toml  # terminal config
└── dank-theme.toml # colors generated by DMS
fish/               # ~/.config/fish: config.fish, prompt, theme, key bindings, universal variables
cursor/
├── Hacked-Red/     # ~/.icons/Hacked-Red: the cursor theme
├── index.theme     # ~/.icons/default/index.theme: fallback cursor theme
└── 90-cursor.conf  # ~/.config/environment.d: XCURSOR_THEME and XCURSOR_SIZE
icons/              # ~/.icons: Sweet-Red icon theme (set in DMS) + candy-icons (its base)
ssh-agent/
└── 90-ssh-agent.conf # ~/.config/environment.d: SSH_AUTH_SOCK for gcr-ssh-agent
claude/
├── *.jsonl         # Claude Code session(s) used to build this setup
└── memory/         # Claude Code memory for this project
wallpaper/          # the wallpaper currently in use
```

## Backup and restore

```sh
# Save the current state (after changing something in Hyprland or DMS)
./backup.sh

# Restore the saved config
./restore.sh
dms restart
```

- `backup.sh` replaces whatever is in this folder with the current system config.
  Only `*.lua` files are copied from `~/.config/hypr` (leftovers like `hyprland.lua.orig`
  are skipped).
- `restore.sh`:
  1. Installs the missing packages (see [Fresh install](#fresh-install)).
  2. Checks that the saved config is valid with `Hyprland --verify-config`
     (this also checks the files in `hypr/dms/`).
  3. Backs up your current system config to `~/.config-backups/<date>/`.
  4. Copies everything, installs `fish`/`zoxide` if missing and makes fish the default shell.
- Hyprland reloads its config on save (or `hyprctl reload`); DMS needs `dms restart`.
- Only the wallpaper in use is saved, not the whole `~/.wallpapers` folder. On restore,
  it is copied to its original path if it is missing.

> **Shared with niri:** `dms/`, `alacritty/`, `fish/`, `cursor/`, `ssh-agent/` and the
> wallpaper are the same files the niri repo saves, since both sessions use them.
> Restoring one repo overwrites them with that repo's version.

## Fresh install

Works on a fresh **Fedora Workstation** or a **minimal Fedora install** (e.g. the
"Minimal Install" of the Everything netinstaller, which boots to a text console).

```sh
sudo dnf install git     # a minimal install has no git
git clone https://github.com/mirko-geno/hyprland-dms-config.git ~/hyprland-dms-config
cd ~/hyprland-dms-config
./restore.sh   # asks for sudo (packages, login screen) and your password (chsh to fish)
```

The repo is private: cloning over HTTPS asks for a GitHub username and a personal access
token (or set up an SSH key first and use the `git@github.com:` URL).

- **Workstation:** log out and pick **Hyprland** in GDM (gear icon at the bottom right).
  GDM is kept; the DMS greeter is not installed.
- **Minimal install:** reboot. There was no display manager, so `restore.sh` sets up greetd
  with the DMS greeter (themed like the desktop) and makes the system boot to the
  graphical target.

`restore.sh` installs only the packages that are missing (checked by what they provide, so
replacements like `mesa-vulkan-drivers-freeworld` count), so on a system that is already
set up it does not ask for sudo:

| Source | Packages |
|---|---|
| [`avengemedia/dms`](https://copr.fedorainfracloud.org/coprs/avengemedia/dms/) COPR (+ its dependency repo `avengemedia/danklinux`) | `dms` (pulls `dms-cli`, `quickshell`), `danksearch`, `matugen`, `dgop`; `dms-greeter` (login screen, minimal install only) |
| [`lionheartp/Hyprland`](https://copr.fedorainfracloud.org/coprs/lionheartp/Hyprland/) COPR (recommended by the Hyprland wiki) | `hyprland`, `xdg-desktop-portal-hyprland`, `hyprland-guiutils`, `hyprland-devel` (to build hyprexpo; same version as an installed `hyprland`) |
| Fedora | `alacritty`, `fish`, `zoxide`, `gcr`, `gnome-keyring`, `breeze-icon-theme`, `xdg-desktop-portal-gtk`, `lua-devel` and `make` (hyprexpo) (and `dnf5-plugins` for `dnf copr`) |
| Fedora: desktop basics a minimal install lacks | graphics `mesa-dri-drivers`, `mesa-vulkan-drivers`; audio `pipewire`, `pipewire-pulseaudio`, `wireplumber`; battery/power `upower`, `power-profiles-daemon`; `NetworkManager-wifi`, `bluez`; `polkit`, `xdg-utils`, `xdg-user-dirs`; `python3`, `git-core` (used by `restore.sh` and `hyprexpo.sh`); fonts `google-noto-sans-vf-fonts`, `google-noto-sans-mono-vf-fonts`, `google-noto-color-emoji-fonts`, `fira-code-fonts` (DMS monospace font); `greetd` (minimal install only) |

- DMS packages are installed with weak deps (DMS recommends `cava`, `qt6ct`,
  `qt6-qtmultimedia`...). Hyprland is installed without them: they would pull `nwg-panel`,
  `wofi` and `kitty`, which DMS already covers.
- `hyprland-guiutils` holds the small dialog apps Hyprland runs itself: `hyprland-dialog`
  (the "app not responding" prompt and permission requests), the update news and donation
  screens, a welcome screen and `hyprland-run` (a launcher; not bound to any key here, DMS
  covers it). Without it Hyprland shows a "missing hyprland-guiutils" warning on every login
  and can't offer to kill a frozen app.
- The Hyprland COPR also ships `quickshell` and `matugen`; they are excluded from it
  (`excludepkgs`) so the versions DMS depends on are kept.
- DMS runs as the `dms.service` systemd user service; `restore.sh` adds it to
  `hyprland-session.target` (what `dms setup` does), so it starts with the Hyprland session.
- DMS file search (typing `/name` in the launcher) asks the `dsearch` daemon (`danksearch`
  package), which indexes the home folder. Its user service ships disabled, so `restore.sh`
  enables `dsearch.service`; without it the search returns nothing. The first index takes a
  while after login.
- Bluetooth (`bluetooth.service`) is enabled if it isn't.
- Login screen (only when `/etc/systemd/system/display-manager.service` does not exist):
  `restore.sh` writes `/etc/greetd/config.toml` (user `greeter`, command
  `/usr/bin/dms-greeter --command hyprland`), enables `greetd.service`, sets
  `graphical.target` as default and runs `dms-greeter sync` to copy the DMS theme and
  wallpaper to it. Fedora's `/etc/pam.d/greetd` already unlocks gnome-keyring at login.
- NVIDIA GPUs need the proprietary driver from RPM Fusion, which is not handled here
  (Intel/AMD work with Mesa).
- Apps (browser, file manager, editor...) are not installed by `restore.sh`.
- Untested on an actual minimal install yet: try it in a VM first.

Manual equivalent of the package part (Workstation):

```sh
sudo dnf copr enable avengemedia/dms
sudo dnf copr enable lionheartp/Hyprland
sudo dnf config-manager setopt "copr:copr.fedorainfracloud.org:lionheartp:Hyprland.excludepkgs=quickshell,matugen"
sudo dnf config-manager setopt terra.excludepkgs=glaze-devel   # Nobara only (see Workspace overview)
sudo dnf install dms danksearch matugen dgop alacritty fish zoxide gcr gnome-keyring breeze-icon-theme xdg-desktop-portal-gtk lua-devel make
sudo dnf install --setopt=install_weak_deps=False hyprland xdg-desktop-portal-hyprland hyprland-guiutils hyprland-devel
systemctl --user add-wants hyprland-session.target dms.service
systemctl --user enable --now dsearch.service
./hyprexpo.sh
```

## How DMS is started

`hyprland.lua` (generated with `dms setup headless --compositor hyprland`) starts
`hyprland-session.target` on launch, which pulls in `graphical-session.target` and with it
the `dms.service` systemd user service, the same way the niri session does.

## Changes from the DMS-generated config

- `kb_layout = "latam"` in `hyprland.lua`: unlike niri, Hyprland does not read the system
  keyboard layout (`localectl`), and an empty value falls back to `us`.
- `float_switch_override_focus = 0` in `hyprland.lua`: focus doesn't follow the mouse
  (`follow_mouse = 0`), but by default Hyprland still moves the focus when the cursor
  crosses between a floating and a tiled window. With floating windows smaller and centered
  (`floating.lua`), that made the focus jump off a window just made floating.
- `ecosystem.no_donation_nag = true` in `hyprland.lua`: no donation screen. The update news
  screen after a Hyprland update is kept.

## Other keybind changes

In `hypr/dms/binds-user.lua` (the DMS file for user binds; the DMS keybind editor keeps
only its `hl.bind` / `hl.unbind` lines):

- `Alt + F4` closes the focused window; the stock `Super + Q` is removed.
- `Super + Space` opens the DMS search bar (`spotlight-bar`, stock `Alt + Space`) instead of the
  app panel (`spotlight`); `Alt + Space` does nothing.
- `Super + V` toggles floating; the stock `Super + Shift + T` is removed. `Super + V` was
  the DMS clipboard history, which moved to `Super + C`. The bind lives in
  `hypr/floating.lua` (not in `binds-user.lua`, whose non-bind lines the DMS keybind editor
  drops): a window that becomes floating is resized to 30% of its monitor's area (same
  proportions as the monitor, about 55% x 55%) and centered, instead of keeping its tiled
  size, which often left part of it outside the monitor. Change `FLOAT_AREA` to adjust.
- Left-handed focus, like the niri setup: `Super + 1 / 2 / 3 / 4` = left / right / up / down.
  The stock `Super + H J K L` are removed; `Super + arrows` are kept.
- `Super + 5…9` removed (workspaces are switched only with F keys, see [Workspaces](#workspaces)).

## DMS bar

Two bars in `dms/config/settings.json` (`barConfigs`), each tied to screens by name:

| Bar | Screens | Difference |
|---|---|---|
| Main Bar | the portrait monitor (`HDMI-A-1`) | no battery widget |
| Laptop Bar | `eDP-1`, `eDP-2` (a laptop's built-in panel uses one of those names) | same widgets + battery |

DMS matches plain strings against the output name, so the Laptop Bar only appears on a
machine with a built-in screen. The battery widget lives only there because on a machine
without a battery DMS still shows it, as a generic icon.

The Laptop Bar is a copy of the Main Bar: a widget change made in DMS settings to one bar
is not applied to the other.

## Stack layout

`hypr/stack.lua` registers a custom Lua layout (`lua:stack`), used on every workspace.
It is loaded last from `hyprland.lua`, so its binds replace the DMS stock ones.

A workspace is a row of equal **cells** along the long side of the monitor: columns on
landscape monitors, rows on portrait ones. Each cell is tiled like dwindle.

| Shortcut | What it does |
|---|---|
| `Super + T`, `Super + Space` (and any app opened another way) | Normal: splits the focused window in half, side by side if it is wider than tall, top/bottom otherwise (direction kept afterwards, like `preserve_split`) |
| `Super + Alt + T` | Opens a terminal as a new cell: 100% → 50/50 → 33/33/33… |
| `Super + Alt + Space` | Same, for the app picked in the DMS search bar (the next window that opens) |
| `Super + Ctrl + 1 / 2 / 3 / 4` (or `Super + Shift + arrows`) | Swaps the focused window with its neighbor left / right / up / down (left-handed, like niri; the stock `Super + Shift + H J K L` are removed) |
| `Super + R` | Toggles the focused window's split between side by side and top/bottom |
| `Super + right drag` (on a tiled window) | Resizes: moves the window's borders with the cursor |
| `Super + =` / `Super + -` | Grows / shrinks the focused window (hold to repeat) |
| `Super + Shift + R` | Back to equal sizes on the workspace |
| `Super + 1 / 2 / 3 / 4` (or `Super + arrows`) | Focus left / right / up / down (generic Hyprland, set in `binds-user.lua`) |

- Closing (or floating, or moving away) a window gives its space back: its split partner
  takes the whole space, an empty cell disappears and the cells are re-split equally.
- When stacking, normal windows already split in the stack direction (top/bottom on
  portrait, side by side on landscape) become cells of their own first. Example on the
  portrait monitor: two normal windows one above the other, then `Super + Alt + T` →
  33/33/33 (not 25/25/50). Splits in the other direction stay as one cell: a normal
  window with two side-by-side windows below it, then `Super + Alt + T` → three equal
  rows, the middle one shared by the two side-by-side windows.
- Resizing: Hyprland's resize requests (mouse resize, `window.resize`) don't reach Lua
  layouts either, so the layout takes messages: `resize <dx> <dy>` (pixels), `grow <fraction>`
  and `equalize`. `Super + right drag` is emulated: the bind finds the tiled window under the
  cursor, focuses it and starts a 16 ms timer that sends the cursor movement as `resize`
  until the button is released. The border that moves is the nearest one in each direction
  (inside the cell first, then between cells). Floating windows keep the DMS stock resize
  bind. Stacking or closing a cell goes back to equal cells; split ratios stay.
- The drag timer is created on first use: creating an `hl.timer` while the config loads
  crashes `Hyprland --verify-config`, which `restore.sh` runs.
- Generic `window.move` / `window.swap` don't reach Lua layouts, so moving goes through the
  layout message `move l|r|u|d` (`hl.dsp.layout("move l")`). Ties between equally close
  windows go to the most aligned one, then the most recently focused.
- The layout state lives in Lua: a config reload (e.g. saving any file in `~/.config/hypr`)
  re-tiles the existing windows as normal splits.
- If `Super + Alt + Space` is used and the search bar is closed without opening anything, the
  next window opened later still goes to a new cell.

## Workspaces

`hypr/workspaces.lua` pins workspaces to monitors with workspace rules, following the
keyboard's F-key groups (F1–F4, gap, F5–F8):

| Shortcut | What it does |
|---|---|
| `Super + F1` … `Super + F4` | Workspaces 1–4, always on the landscape monitor (DP-1) |
| `Super + F5` … `Super + F8` | Workspaces 5–8, always on the portrait monitor (HDMI-A-1) |
| `Super + Ctrl + F1` … `F8` | Send the focused window to that workspace |

- Each monitor starts on its first workspace (1 and 5).
- Going to a workspace on the other monitor moves the focus (and the cursor) there.
- The DMS stock `Super + 1…9` binds are removed (in `hypr/dms/binds-user.lua`): workspaces
  are switched only with the F keys. `Super + Shift + 1…9` (send window) still exists;
  numbers are global, so `Super + Shift + 5` sends to workspace 5 on the portrait monitor.
- Workspaces are created when visited and removed when empty and not shown.
- The monitor names are hard-coded: on another machine, update them in `workspaces.lua`.

## Workspace overview

`Super + Tab` opens [hyprexpo](https://github.com/sandwichfarm/hyprexpo) (a maintained fork
of the plugin dropped from `hyprland-plugins`) on both monitors: a 2x2 grid per monitor,
workspaces 1–4 on DP-1 and 5–8 on HDMI-A-1, empty ones included. Click a tile or press its
number to go there, arrows + Enter to pick one, Escape to cancel; windows can be dragged
between tiles. Settings and bind are in `hypr/hyprexpo.lua`.

The plugin is not managed by `hyprpm`: `hyprexpo.sh` builds it against `hyprland-devel`
from the Hyprland COPR (exact match for the installed Hyprland, no headers to build, no
`sudo` for `hyprpm`) and installs it to `~/.local/lib/hyprexpo/hyprexpo.so`, which
`hyprexpo.lua` loads with `hl.plugin.load`. `restore.sh` runs it (and installs
`hyprland-devel`, `lua-devel` and `make`). After a Hyprland update:

```sh
sudo dnf upgrade hyprland hyprland-devel   # both must be the same version
./hyprexpo.sh                              # then log out and back in
```

- The script takes the Hyprland commit from the `hyprland-devel` headers, checks it matches
  the installed `Hyprland`, and builds the plugin commit the fork pins for it in
  `hyprpm.toml`. It doesn't build anything when there is no pin yet for a new Hyprland
  version (try again later).
- It does nothing if the plugin is already built for the installed Hyprland package (its
  version-release is saved in `~/.local/lib/hyprexpo/hyprland-build`); `./hyprexpo.sh --force`
  rebuilds anyway. Building takes about 2 minutes. The package release counts, not only the
  commit: the COPR rebuilds the same Hyprland commit against new libraries (e.g. `0.57.2-2`,
  against `hyprgraphics` 0.7), and a plugin built for the old build doesn't load.
- If the running Hyprland is the installed binary, it loads the new plugin right away and
  reloads the config (the stack layout re-tiles open windows). Right after an update the
  session still runs the old binary, so it only loads on the next login.
- On Nobara, the `terra` repo ships a newer `glaze-devel` (9.x) without the `glaze-static`
  that `hyprland-devel` requires (the COPR's 8.x has it), which blocks system updates.
  `restore.sh` excludes it from terra (added to terra's own exclude list, Nobara's entries
  stay): `sudo dnf config-manager setopt terra.excludepkgs=glaze-devel`.
- It is installed with `install`, never `cp`: writing over a loaded `.so` crashes Hyprland.
- Lua: the fork requires Lua 5.5 (what upstream Hyprland 0.57 uses), but the COPR builds
  Hyprland against Fedora's Lua 5.4, and the plugin must use the same Lua as Hyprland. The
  plugin only calls Lua C functions that are the same in 5.4 and 5.5, so the script skips
  the fork's version check (`make -o check-lua`) after checking that `lua-devel` is the Lua
  Hyprland links.
- A plugin built for another Hyprland version doesn't load. Until it is rebuilt, `Super + Tab`
  falls back to the DMS overview; the same happens when the `.so` is missing, and the plugin
  settings are skipped.
- `Hyprland --verify-config` doesn't load plugins, so the settings are skipped there too.
- Labels show the workspace number (`label_text_mode = "id"`), not the tile position.

## Cursor

Apps not started by the compositor fall back to the `default` cursor theme, which is
Adwaita, unless these two files are in place:

- `~/.icons/default/index.theme` makes `Hacked-Red` the fallback theme.
- `~/.config/environment.d/90-cursor.conf` sets the theme and size for the whole session
  (applied on the next login).

## Screen sharing

Screen sharing goes through `xdg-desktop-portal-hyprland`. Apps that don't say whether they
want the cursor (Vesktop/Discord) got the portal's default, hidden, so the cursor was
missing from the share. `hypr/xdph.conf` sets `screencopy:cursor_mode = 2` (embedded) as the
default; apps that ask for a mode still get theirs.

Vesktop (like any Chromium/Electron app) opens a new portal session after the pick, for the
real capture, and reuses the pick through a restore token. The picker only hands out that
token when "Allow a restore token" is ticked, which it isn't by default, so the picker kept
popping up again. `screencopy:allow_token_by_default = true` ticks it by default (Vesktop
asks for `persist_mode 1`: the token only lives while the app runs).

The portal reads `xdph.conf` on start:
`systemctl --user restart xdg-desktop-portal-hyprland` (stops any share in progress).

## SSH agent

Uses `gcr-ssh-agent` (from GNOME's `gcr`, works without the GNOME session): the SSH key
passphrase is asked once per session in a popup.

- `systemctl --user enable --now gcr-ssh-agent.socket` (done by `restore.sh`).
- `~/.config/environment.d/90-ssh-agent.conf` sets `SSH_AUTH_SOCK=${XDG_RUNTIME_DIR}/gcr/ssh`.

## Claude Code session

`claude/` holds the Claude Code session where this setup was built, plus its memory.
`restore.sh` puts them back in `~/.claude/projects/<repo path with "-">/`, so the
session can be resumed from the repo folder:

```sh
cd ~/hyprland-dms-config
claude --resume b72d4f5c-b8ea-4bf6-810c-f3d731982a15
```

That session is very long, so resuming it is expensive. For new work, start a new session in
the repo folder: `CLAUDE.md` (rules, workflow, pitfalls) and the project memory give it the
context.

The session includes command outputs from this machine (paths, packages, email),
so the repo should stay private.
