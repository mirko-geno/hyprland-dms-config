User is trying Hyprland 0.57 (Lua config: ~/.config/hypr/hyprland.lua + dms/*.lua via require) as a tiling alternative to niri, both with DMS, picked as sessions in GDM. Repo ~/hyprland-dms-config (private, GitHub mirko-geno/hyprland-dms-config) mirrors the niri repo structure ([[niri-dms-setup]]): backup.sh / restore.sh / README in English; hypr/ instead of niri/; dms, alacritty, fish, cursor, ssh-agent, wallpaper and claude/ are the same as in the niri repo (shared files, restoring one repo overwrites them).

restore.sh is meant for a fresh Fedora Workstation: installs missing packages (avengemedia/dms COPR, which auto-enables avengemedia/danklinux for quickshell/matugen/dgop/danksearch; lionheartp/Hyprland COPR with quickshell,matugen excluded and no weak deps; alacritty fish zoxide gcr gnome-keyring breeze-icon-theme xdg-desktop-portal-gtk from Fedora), adds dms.service to hyprland-session.target, restores icons/ (Sweet-Red + candy-icons from ~/.icons). Not yet tested on an actual clean Fedora. Branch fedora-minimal (2026-11-17, not merged): restore.sh also installs desktop basics for a minimal install (mesa, pipewire, upower, ppd, NM-wifi, bluez, noto vf + fira-code fonts, xdg tools), checks packages with rpm -q --whatprovides, and if no display-manager.service exists installs greetd + dms-greeter, writes /etc/greetd/config.toml (dms-greeter --command hyprland), enables greetd, graphical.target, runs dms-greeter sync. User wants it tested in a VM first. The niri repo installs neither niri nor DMS. Validate with `Hyprland --verify-config -c <file>` (prints "config ok"; checks required dms files relative to that file). Only change from DMS-generated config so far: kb_layout = "latam" (Hyprland ignores localectl). Custom Lua layout ~/.config/hypr/stack.lua (lua:stack, required last in hyprland.lua): equal cells along the monitor long side (Super+Alt+T / Super+Alt+Space add a cell via a pending flag), dwindle-like splits inside cells for normal windows, move via layout msg "move l/r/u/d" (generic window.move/swap don't reach Lua layouts), togglesplit/swapsplit, resize dx dy / grow / equalize (Super+right drag emulated with a lazily created hl.timer reading the cursor; Super+=/-; Super+Shift+R). Creating hl.timer at config load segfaults Hyprland --verify-config. Always edit stack.lua in a scratch copy, test it on a headless output and verify the full config before copying it in: saving it reloads the live session. Test Lua layouts on a headless output (`hyprctl output create headless NAME`, `hyprctl eval`, workspace_rule with layout) under a fresh layout name each time: re-registering a name errors; any save in ~/.config/hypr reloads config and resets Lua state. ~/.config/hypr/workspaces.lua: workspace rules pin 1-4 to DP-1 (landscape), 5-8 to HDMI-A-1 (portrait), Super+F1..F8 focus, Super+Ctrl+F1..F8 move window (user's keyboard groups F1-F4 / F5-F8). dms/binds-user.lua: Super+1..4 focus l/r/u/d (HJKL unbound, arrows kept), Super+5..9 and Super+Q unbound, Alt+F4 closes, Super+V toggles floating (replaced Super+Shift+T; DMS clipboard moved to Super+C), Super+Space = DMS search bar (spotlight-bar), Alt+Space unbound, Super+Alt+Space stacks via spotlight-bar; stack.lua binds Super+Ctrl+1..4 (and Super+Shift+arrows) to layout move (explicit hl.bind/hl.unbind lines only, the DMS editor keeps just those). Left-handed scheme mirrors niri's; stock DMS binds use Super+1..9 for workspaces.

**Why:** user wants each compositor setup reproducible on its own.
**How to apply:** after config changes run the validator, ./backup.sh, update README; new config files go in backup.sh/restore.sh too. User commits/pushes themselves. `sudo` doesn't work through `!` in Claude Code: give the user sudo commands to run in their own terminal.
